## How I approach engineering

1. **Start with the failure mode.** Identify what can break, how it becomes visible, and how the system recovers.
2. **Protect data and boundaries.** Make unsafe states difficult to represent and authorization rules difficult to bypass.
3. **Prefer evidence over claims.** Support decisions with tests, reviewed migrations, documented trade-offs, and reproducible results.
4. **Design for the next maintainer.** Choose clarity and named responsibilities over clever abstractions.
